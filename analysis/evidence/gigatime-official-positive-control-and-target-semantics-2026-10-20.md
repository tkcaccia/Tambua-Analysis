# Official GigaTIME positive control and output semantics

The [official GigaTIME repository](https://github.com/prov-gigatime/GigaTIME#data) supplies 50 paired H&E/COMET test patches. Its 418,489,537-byte `sample_test_data.zip` was downloaded locally and passed ZIP CRC validation (SHA-256 `cd1212b361f7bfe4f7f01779a59f437c691fd43a684d7b5f584c37bf7d0e2601`). The archive contains 50 RGB H&E PNGs, 50 25-channel raw COMET NumPy arrays, and associated mask/metadata files. One fixed pair, `0_556_556_556`, has been staged on Chiamaka as a **CPU-only future positive control** at `/home/chiamaka/Tambua-gigatime-official-positive-control-2026-10-20/input`. The lossless RGB OME-TIFF and raw COMET channel-0 OME-TIFF are 556 × 556 pixels with a declared source spacing of 128/556 = 0.2302158 µm/pixel. Transfer hashes were checked on both machines. No model inference or classification has yet been run on this pair. Channel 0 visually resembles nuclear fluorescence, but the exact raw COMET-to-model channel map must be verified before calling it measured DAPI in a quantitative comparison.

The [authors' training script](https://github.com/prov-gigatime/GigaTIME/blob/main/scripts/db_train.py) explicitly downsamples each 512-pixel marker target eightfold with bilinear interpolation, then upsamples it back to 512 pixels before computing loss. At the [authors' clarified physical field size](https://github.com/prov-gigatime/GigaTIME/issues/4) of 128 µm per 512 model pixels, the supervised target's intermediate grid has 64 samples across 128 µm, or **2 µm per coarse sample**. The [dataset code](https://github.com/prov-gigatime/GigaTIME/blob/main/scripts/prov_data.py) constructs cell-level, binarized marker masks for those targets. GigaTIME output therefore must be treated as an **uncalibrated virtual marker score**, not measured fluorescence intensity or guaranteed single-nucleus contours. CellPhenotyper already records this value semantics in its output metadata.

This training design can contribute to broad virtual-DAPI peaks, but it does **not** by itself explain the MoNuSAC QC failures. In the prior [ideal coarse-target audit](monusac-expanded-output-qc/first-twenty-one-ideal-coarse-qc.json), a perfect eightfold-coarsened StarDist mask passed the unchanged nuclear gate in all first 21 fields, while the actual virtual DAPI failed all 21. That optimistic self-mask control does not measure real model accuracy. The official paired positive control is the next discriminator: compare the same pinned inference code and calibrated RGB input against the native paired image before attributing poor transfer to stain/domain shift or editing QC thresholds. Even a good official control would not validate protein-specific correlation on ORION or four-class cell typing on MoNuSAC.

No UCT HPC GPU work was used. The live 93-field Chiamaka CPU bundle and the separately approved one-field ORION GPU pilot remain unchanged.
