# GigaTIME input audit for the MoNuSAC expansion

This audit does not declare the virtual proteins valid. It compares the currently deployed input contract with the model authors' public example and records a paired positive control before any new inference campaign.

- The [official model card](https://huggingface.co/prov-gigatime/GigaTIME) describes an RGB `[B,3,256,256]` input and 23 spatial output channels. CellPhenotyper's current runner uses 256 × 256 model-grid patches and the same ordered 23 channels.
- The [authors' data loader](https://github.com/prov-gigatime/GigaTIME/blob/main/scripts/prov_data.py) converts source H&E with PIL `.convert("RGB")`; it does not use OpenCV BGR. CellPhenotyper loads scanner RGB, preserves that channel order, and uses ImageNet mean/std normalization, matching the [authors' notebook](https://github.com/prov-gigatime/GigaTIME/blob/main/scripts/gigatime_testing.ipynb). The completed-case renderer checks each scanner-RGB file hash against its inference checkpoint. Visual H&E colors in the first 11 contact sheets are plausible. These checks do not establish that every upstream scan was color-calibrated.
- Source pixel spacing in completed case `TCGA-49-6743-01Z-00-DX2_005` is 0.252 µm/px; CellPhenotyper recorded an effective 0.25 µm/px. It pinned GigaTIME revision `a6556030bdb8071857559e12b921620aa1bbac5b` and verified checkpoint SHA-256 `d200308302c7fefd13b259c62de546f2c859c28d1079e9f67dc8808915d95d0c`.
- The authors' public notebook shows 556 × 556 source H&E tiles resized to 512 × 512 in its dataset transform. Its `do_inference` then runs the model on four non-overlapping 256 × 256 windows. Thus the 512-pixel example does **not** imply a 512-pixel CNN input; the current CellPhenotyper 256-pixel patch size agrees with this test-time model call. The notebook does not establish the source physical pixel spacing for every independent dataset, so the 0.25 µm/px deployment still needs a calibrated paired positive control.
- Downloaded the authors' [50-patch paired test archive](https://github.com/prov-gigatime/GigaTIME#data) to Chiamaka as `/home/chiamaka/Tambua-gigatime-official-reference-2026-10-20/sample_test_data.zip`; integrity passed, size 418,489,537 bytes, SHA-256 `cd1212b361f7bfe4f7f01779a59f437c691fd43a684d7b5f584c37bf7d0e2601`. Extracted only one 556 × 556 RGB H&E patch and its measured mIF/segmentation files for a future bounded positive-control comparison. No model inference was launched from this reference data in this audit.
- All first 11 expansion images failed the fixed virtual-DAPI versus StarDist QC. Seven failed nuclear alignment alone; four also failed spatial-shadow QC. Manual review of all 11 display-scaled contact sheets agrees that none should enter the validated classifier cohort. Several virtual DAPI fields are diffuse despite plausible scanner RGB and a passing seam check. There is no evidence here that swapping red and blue would correct them.

No QC threshold was changed after viewing the test images. The live CPU-only 93-image bundle is source-frozen and was not modified or restarted during this audit. UCT HPC GPU work remains paused.

Follow-up CPU-only stain preflight: aggregate tissue-color statistics from the 50 author-supplied H&E patches differ substantially from two QC-failing MoNuSAC fields. One lung field's median RGB tissue value is `[163,105,156]`, versus `[213,191,214]` in one author patch; the kidney field is strongly eosin-pink. A full-LAB color transfer introduced conspicuous cyan nuclear artifacts in the kidney field and was rejected. A bounded luminance-only transform preserved hue and microscopy geometry in three visual previews, but no GigaTIME inference or DAPI improvement has yet been demonstrated. See [preflight evidence](../gigatime-stain-preflight/visual-review.json). The current 93-image run still uses its original immutable scanner RGB inputs.
